# Архітектура Buyer Italia

Мета структури — за назвою імпорту одразу знаходити реальну реалізацію, без ланцюжків реекспортів і зайвих абстракцій.

## Основні директорії

```text
app/          маршрути, metadata та композиція сторінок
actions/      серверні операції, згруповані за функціональною областю
components/   UI-компоненти та локальний стан інтерфейсу
lib/          спільна інфраструктура, інтеграції, типи та утиліти
docs/         технічні й бізнес-рішення
```

## Структура actions

```text
actions/
  catalog/
    get-product.ts
    get-products.ts
    get-filter-options.ts
  checkout/
    submit-order.ts
```

Правила:

1. Один файл містить одну публічну операцію.
2. Імпорт завжди веде безпосередньо до файла реалізації.
3. Не використовуємо barrel-файли `index.ts` та файли, які лише реекспортують іншу функцію.
4. Схема валідації та приватні допоміжні функції залишаються поруч з операцією, доки не з’являться щонайменше два реальні споживачі.
5. `"use server"` використовується для мутацій, які викликає Client Component.
6. Серверні функції читання позначаються `import "server-only"` і викликаються із Server Components.

## Межі відповідальності

- `actions` описує конкретний сценарій застосунку: отримати каталог або оформити замовлення.
- `lib/obriym` знає лише про протокол Obriym CRM: авторизацію, URL, HTTP-запити та CRM-типи.
- `components` не звертаються до CRM або бази напряму.
- Дані з браузера завжди недовірені. Ціна, доступність і залишок повторно читаються із CRM на сервері.
- Server Action повертає тільки результат, необхідний інтерфейсу; сирі відповіді CRM клієнту не передаються.

## Коли потрібен Route Handler

Route Handler створюється лише для зовнішнього HTTP-виклику: webhook CRM, платіжного провайдера або служби доставки. Внутрішні дії інтерфейсу виконуються Server Actions.

## Стиль функцій

- назва починається з дії: `getProducts`, `getProduct`, `submitOrder`;
- не більше одного рівня зайвого перенаправлення;
- раннє повернення для невалідних станів;
- приватні функції мають одну чітку відповідальність;
- нова абстракція додається лише коли усуває реальне дублювання або відокремлює зовнішню систему.
